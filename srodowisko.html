Przygotowanie środowiska

Język Java · 2026/27

I. Środowisko Java

Do tworzenia i uruchamiania programów w Javie zalecane jest korzystanie z jednego z poniższych środowisk:

E

Eclipse

Popularne środowisko programistyczne przeznaczone między innymi do pracy z Javą.

I

IntelliJ IDEA

Nowoczesne środowisko programistyczne firmy JetBrains, dobrze przystosowane do nauki i tworzenia aplikacji w Javie.

Rekomendowane są Eclipse oraz IntelliJ IDEA. W przypadku tych środowisk nie ma potrzeby osobnej instalacji Javy — środowisko może zająć się odpowiednią konfiguracją potrzebnych komponentów.

Korzystanie z innych środowisk lub konfiguracji nie jest zalecane, ponieważ może powodować problemy ze zgodnością z zadaniami i środowiskiem testowym.

II. GitHub

Kod wszystkich zadań należy przechowywać na GitHubie.

Każdy student musi utworzyć prywatne repozytorium, w którym będzie przechowywany kod rozwiązań.

1

Utwórz prywatne repozytorium

Repozytorium powinno być prywatne i przeznaczone do przechowywania rozwiązań zadań.

2

Dodaj prowadzącego jako Collaboratora

Do repozytorium należy dodać prowadzącego jako Collaboratora, aby możliwe było przeglądanie kodu.

Nazwa użytkownika: js-ivy

III. Środowisko testowe

Do sprawdzania rozwiązań wykorzystywany jest bot działający bezpośrednio z GitHubem.

Bot otrzymuje dostęp wyłącznie do repozytorium z kodem zadań. Nie należy udostępniać mu dostępu do innych repozytoriów.

↗
Przejdź do instalacji bota Otwórz stronę bota GitHub i skonfiguruj dostęp do swojego repozytorium.
1

Zainstaluj bota GitHub

Bot musi zostać zainstalowany w ramach konta GitHub i otrzymać dostęp do odpowiedniego repozytorium.

2

Ogranicz dostęp do jednego repozytorium

Podczas instalacji należy wybrać opcję ograniczającą dostęp bota do jednego, konkretnego repozytorium zawierającego rozwiązania zadań.

Jak działa środowisko testowe?

1

Przesyłasz kod

Rozwiązanie zadania umieszczasz w swoim repozytorium GitHub.

↓
2

Bot pobiera kod

Środowisko testowe pobiera odpowiedni kod z Twojego repozytorium.

↓
3

Uruchamiane są testy

Kod jest uruchamiany w środowisku testowym, a przygotowane testy sprawdzają poprawność rozwiązania.

↓
4

Otrzymujesz wynik

Wynik testów jest zwracany w zamkniętym wątku GitHub Issues.

Automatyczne sprawdzanie zmian

Jeżeli dla danego zadania dostępne są już testy, środowisko testowe automatycznie monitoruje repozytorium.

Bot okresowo sprawdza czy w repozytorium pojawiła się zmiana kodu.

Jeżeli kod został zmieniony, bot uruchamia testy wyłącznie tych zadań, których kod został zmieniony. Nie są ponownie uruchamiane testy wszystkich zadań.

Struktura repozytorium

Każde zadanie musi znajdować się w folderze o nazwie określonej z góry w treści zadania.

Jest to wymagane przez środowisko testowe, ponieważ bot wykorzystuje nazwę folderu do określenia, którego zadania dotyczą zmiany i jakie testy należy uruchomić.

Dodatkowo klasa implementująca rozwiązanie również będzie wymagała określonej nazwy, ponieważ w innym przypadku testy nie mogłby być uniwersalne.

Przykładowa struktura 

            repozytorium/
            │
            ├── zadanie01/
            │   └── OkreslonaNazwa.java
            │   └── ...
            │
            ├── zadanie02/
            │   └── OkreslonaNazwa.java
            │   └── ...
            │
            ├── zadanie03/
            │   └── OkreslonaNazwa.java
            │   └── ...
            │
            └── ...
Ważne: Nazwy folderów oraz implementacji zadań należy zachować dokładnie w formie podanej w treści danego zadania. Zmiana nazw może uniemożliwić prawidłowe uruchomienie testów, a co za tym idzie brak zaliczenia zadania w danym terminie.
